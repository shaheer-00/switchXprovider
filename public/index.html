Help & Troubleshooting

common issues and how to fix them

🔧 claude-mem stops capturing sessions

proxy is working fine, but claude-mem shows "no API key configured" or zero batches

Why it happens: claude-mem's worker reads API credentials from ~/.claude-mem/.env, not from settings.json. When the proxy changes the base URL and token in settings.json, claude-mem's own .env goes stale — capture dies silently.

Fix: add a hook that keeps claude-mem's credentials in sync automatically:

  1. Add a SessionStart hook that mirrors your credentials into claude-mem's .env on every session. Open ~/.claude/settings.json and add inside "hooks": 
    "SessionStart": [
  {
    "hooks": [
      {
        "type": "command",
        "command": "powershell -ExecutionPolicy Bypass -File \"~/.claude-mem/sync-claude-mem-creds.ps1\""
      }
    ]
  }
]
  2. If capture still doesn't work after adding the hook, restart the worker: 
    node ~/.claude/plugins/cache/thedotmack/claude-mem/*/scripts/worker-cli.js restart

The sync script (included with claude-mem) reads the base URL, auth token, and haiku model ID from settings.json and writes them to ~/.claude-mem/.env on every session start — credentials stay in sync automatically.

🗣 "CAVEMAN MODE ACTIVE" showing everywhere

statusline shows caveman prefix on every line, looks messy or throws errors

What it is: caveman plugin's statusline hook is cosmetic — it prepends a mode label to your status line. If the hook script path is stale (plugin updated but path still points at old version), it may show up garbled or fail silently.

Impact: purely visual. Does not affect proxy routing, failover, pricing, or Claude Code functionality.

  1. If it's noisy: edit ~/.claude/settings.json, find "statusLine", and update the path to the current installed version.
  2. Or remove the statusLine entry entirely to suppress it — caveman works fine without the visual indicator.

🔄 Plugin updated but proxy still old

you ran /plugin update but the dashboard shows old features

Why it happens: the running proxy is a Node process from the old install path. Plugin files update on disk, but the live process still serves the old code.

  1. Kill the old proxy — the SessionStart hook starts a new one automatically on your next Claude Code session. Or run: 
    node ~/.claude/plugins/cache/switchx-marketplace/switchXprovider/<NEW_VERSION>/server/ensure.mjs

From v0.1.9+: this is automatic. The hook detects a stale proxy and restarts it in place — you'll see a one-click update popup in the dashboard too.

⚡ Shell environment variables override settings.json

ANTHROPIC_BASE_URL or ANTHROPIC_API_KEY set in shell/profile wins over settings.json

What it is: if ANTHROPIC_BASE_URL, ANTHROPIC_API_KEY, or ANTHROPIC_AUTH_TOKEN are set in your shell environment (via .bashrc, .zshrc, Set-Item Env: in PowerShell, or system-wide env vars), they take priority over settings.json and bypass the proxy entirely.

Symptoms: proxy shows zero traffic; requests go straight to Anthropic.

  1. Check for the conflicting env vars — run echo $env:ANTHROPIC_BASE_URL (PowerShell) or env | grep ANTHROPIC (bash).
  2. Remove them — if they're in ~/.bashrc / ~/.zshrc, comment them out. The installer warns about this but can't see all places.

📉 Provider marked "down" but works fine manually

proxy won't route to a provider you know is up

Why it happens: the proxy received a 500, 429, or network error and set a cooldown (1 min to 60 min). The provider stays "down" until the cooldown expires — even if the provider recovered instantly.

  1. Reset the provider manually in the Providers view (click the provider → reset).
  2. Or wait for the cooldown to expire (shown in the provider row). For 429 errors the proxy respects retry-after headers and won't retry until that window passes.

🎛 Model names don't match between providers

Provider A uses "glm-5.3", Provider B uses "GLM-5.2-Free" for the same model

Why it happens: different providers use different naming for the same model. switchXprovider maps switchx:opus / switchx:sonnet / switchx:haiku to whatever model name you set per-provider, so every provider can use completely different names.

  1. Set the per-provider model IDs in the Providers view.
  2. For pricing, use the Pricing view — it auto-detects same-base model variants and lets you alias them to share one price. Stats stay separate per name, but pricing is unified.

💰 Cost shows $0 for models I use

Estimated cost widget shows near-zero even though I use Claude Opus / GLM / etc.

Why it happens: cost is calculated from the built-in price table at request time. Models not in the table silently get $0. After setting up the proxy, history recorded before prices were set stays at $0.

  1. Go to Pricing and check for unpriced models (amber badges).
  2. Set prices for them.
  3. Click "Recalculate costs" in the Pricing view header to reprice all history. From v0.2.0+ the built-in table includes real market rates for all common models.

📍 Dashboard unreachable at 127.0.0.1:8787

browser shows "this site can't be reached" or connection refused

Possible causes:

  • proxy not started — run node server/ensure.mjs or let the SessionStart hook do it
  • proxy started on a different port — check ~/.claude/switchx/config.json for "port"
  • another process on port 8787 — stop it first
